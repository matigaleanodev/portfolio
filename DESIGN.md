# Design System: Índigo de taller

[Español](DESIGN.es.md)

Revision 4. This repository is the source of the visual decisions of the ecosystem; other repositories adapt a numbered revision and do not redefine it. Any change to a token or a mandatory rule increases the revision. The token front matter lives in this file.

**MUST** rules are acceptance criteria. **SHOULD** rules are recommendations that may be deviated from with a recorded reason. Values marked _derived_ complete the base palette and identity; see Value origin.

## Overview

A professional, technical, sober and personal portfolio: the work comes early and the background stays light in weight.

- MUST keep the M monogram, IBM Plex Sans and IBM Plex Mono, and the indigo identity. No blue substitute and no second identity color.
- MUST lead with evidence (case, figure, article); decoration does not compete with it.
- MUST treat light and dark as two complete themes. Dark has its own canvas, surface and accent; never invert or filter colors.
- Use accent for actions, links and article quotes.
- Decorative gradients are limited to the two short rules in the hero. The header navigation and footer use their published inset highlights.
- SHOULD write labels in sentence case. IBM Plex Mono is for dates, metadata, identifiers and code, not subtitles.

### Why the derived values

- `surface-sunken`: One tonal step instead of a shadow.
- `accent-hover`: Same hue; raises contrast.
- `accent-active`: Same hue; distinct from hover.
- `accent-subtle`: Indigo tint.
- `control-border`: The approved divider does not reach 3:1.
- `focus`: Alias of accent.
- `disabled-bg`: Neutral without accent.
- `disabled-text`: Stays readable although AA exempts it.
- `danger`: Semantic; not an identity color.
- `danger-subtle`: Background for the error role.
- `success`: Semantic.
- `success-subtle`: Background for the success role.
- `warning`: Semantic.
- `warning-subtle`: Background for the warning role.
- `code-bg`: Dark code surface in both themes.
- `code-text`: Approved dark-theme text.
- `code-muted`: Legibility on code-bg.
- `code-keyword`: Legibility on code-bg.
- `code-string`: Legibility on code-bg.
- `code-number`: Legibility on code-bg.
- `code-border`: Control on code background.
- `code-hover`: Tonal step.
- `code-focus`: Approved dark accent.

- MUST consume semantic tokens (`--color-<token>`); no raw hex in component styles.
- MUST switch themes with `prefers-color-scheme`, declare `color-scheme`, set `theme-color` per theme and resolve the theme before first paint. A manual theme switch is not part of this revision.
- `divider` is decorative (below 3:1). A border that identifies a field, button or checkbox MUST use `control-border`.
- `scrim` for modal overlays: `rgb(15 20 28 / 0.56)` in both themes (derived).

## Layout

- Spacing scale: 4, 8, 12, 16, 24, 32, 40, 48, 64, 80px. MUST use scale values for gaps and padding.
- Containers (`box-sizing: border-box`, centered): page `75rem`, form `48rem`, article text `50rem`, article wide `60rem`. Inline padding 24px; 16px on articles below 640px. Container maximums include the padding except for the article columns.
- Breakpoints: 640px, 960px (768px for the chat panel and project grid). Mobile first.
- Section rhythm: 48px below 768px, 80px from 768px. Inside a block: 8–16px; between blocks: 24–32px. The Projects section uses 32px vertical padding on mobile, 48px on tablet and 64px on desktop.
- MUST reflow at 320px with no page-level horizontal scroll; only code, tables and diagrams scroll, inside a focusable region.
- DOM order MUST match visual order.
- Full-height views SHOULD use `dvh` and safe-area insets.

## Elevation & Depth

- Flat by default: depth comes from `canvas` → `surface` → `surface-sunken` and 1px borders.
- Level 0: no shadow (everything in flow, hover included).
- Level 1 (only transient layers opened over content: chat panel and toast; the launcher rests without shadow): `0 12px 32px -12px rgb(15 20 28 / 0.35)` in light, `0 12px 32px -12px rgb(0 0 0 / 0.6)` in dark, plus a 1px `divider` border (derived).
- Stacking: content 0, launcher 40, scrim 50, chat 60, toast 70, skip link 1000.

## Shapes

- Radii: buttons and fields 5px; code blocks and figures 12px; cards 16px; tags pill; suggestion chips and the chat launcher are pill-shaped, the only approved exceptions to the 5px button radius; editorial rules 0.
- Borders are 1px. Article quotes use a 3px accent leading edge.
- Icons: Lucide, 16px inline and 20px in icon buttons, stroke 2, `currentColor`; existing brand SVGs for external profiles. Decorative icons `aria-hidden`; icon-only controls have an accessible name. No emoji as icons.
- Monogram: the existing M vector, one color (`text`), 40px high in the header, beside the name. No tile, gradient, shadow or recoloring; clear space of 8px at least.
- Images: authentic assets only. A caption MUST say whether it is a product illustration or an interface screenshot; never fabricate screens. Logos and seals use `object-fit: contain`; no overlays or filters. Alt describes the content; decorative images use empty alt.
- Declare `width` and `height` (or `aspect-ratio`) for every image; lazy-load only below the first viewport.

## Components

### Buttons: mandatory seven-state contract

Every button variant MUST define Default, Hover, Focus-visible, Active, Disabled, Loading and Selected. A state that does not apply is marked **n/a** with its reason. A new variant or a change of applicability requires adding its full matrix in a new revision. Full coverage is an acceptance criterion for every change that touches buttons and for the final delivery audit.

#### Precedence and combinations

State is resolved in layers:

1. **Availability** (one wins): Disabled > Loading > Active > Hover > Default.
2. **Selection** (persistent, toggle only): combines with the winning availability layer.
3. **Focus-visible**: additive on top of both layers whenever the control has keyboard focus; no state may hide or replace the ring.

| Combination               | Rule                                                                                                                                                                                                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Disabled + Loading        | Not a valid pair. The control that owns a request in flight uses Loading (`aria-disabled`), never native `disabled`; other controls made unavailable by that request use Disabled. If the action becomes unavailable for another reason, remove Loading and render Disabled. |
| Disabled + Hover / Active | No change; no activation.                                                                                                                                                                                                                                                    |
| Disabled + Focus-visible  | Native `disabled` is not focusable. If a control must stay discoverable, use `aria-disabled="true"` with a described reason; it shows Disabled plus the ring.                                                                                                                |
| Loading + Hover / Active  | No change; repeat activation ignored.                                                                                                                                                                                                                                        |
| Loading + Focus-visible   | Loading plus ring; the state itself does not move focus (a flow rule such as the chat’s may).                                                                                                                                                                                |
| Selected + Hover          | `accent-subtle` background, `text` border and label underline; the text and inset border keep `accent`.                                                                                                                                                                      |
| Selected + Active         | Same colors as Selected, plus translateY(1px).                                                                                                                                                                                                                               |
| Selected + Disabled       | Disabled colors; the 2px inset border uses `disabled-text`; `aria-pressed` or `checked` is preserved.                                                                                                                                                                        |
| Selected + Loading        | n/a: the only selectable variant has no Loading.                                                                                                                                                                                                                             |
| Selected + Focus-visible  | Selected plus outer ring; the ring sits outside the 2px inset border.                                                                                                                                                                                                        |

#### Shared rules

- Semantics: actions are `<button type>`; navigation is `<a>` and is not a button variant, even when it looks like one (it follows the link rules; a link styled as primary or secondary borrows the colors of Default, Hover, Focus-visible and Active and has no Disabled, Loading or Selected). Exclusive choices are native radios in a `fieldset`; independent toggles use `aria-pressed`. `aria-expanded` is disclosure, not selection.
- Toggle keyboard: an `aria-pressed` button activates with Enter or Space; a radio group is one Tab stop, arrows move and select, Space selects. The group has a `legend`; if the input is visually hidden, draw the ring on its segment (`input:focus-visible + label`).
- Stable dimensions: 1px border in every variant and state (transparent when invisible); selection uses an inset border. No weight or size change between states.
- Loading: the spinner replaces the icon in icon-only buttons and appears in the side padding of text buttons; the label may change to the progress text (such as “Enviando…”) with the width of the longest label reserved, and the accessible name matches the visible label. Progress and result are written as text (such as “Enviando…”) in a polite status region outside the button that exists before it is updated and, inside a modal, lives within the dialog. With reduced motion the spinner is static and that text MUST be visible.
- Non-color cues: underline, or a 1px inset border on icon-only variants (hover), ring (focus), 1px offset (active), dashed border (disabled), spinner and text (loading), inset border (selected). With reduced motion the active offset is replaced by a 3px inset border in `currentColor` (4px in `accent` when also selected).
- Focus: 3px solid ring, offset 4px (2px inside code toolbars), `focus` token (`code-focus` on code). Never `outline: none` without this ring.
- Transitions: background, color and border 150ms `cubic-bezier(0.2, 0, 0, 1)`; transform 100ms; the focus ring appears instantly.
- Sizes: minimum height 48px for primary and secondary, 44px for the rest, 56px launcher; horizontal padding 16–24px; gap 8px; label style `button-label`. Exception, icon only: 20×20px icon, 1px border and 11px padding on every side, for a final 44×44px.
- Forced colors: rely on system colors. Shadows disappear, so button inset indicators (hover, active, selected) MUST be redrawn with an inner pseudo-element border in `ButtonText` or `Highlight`, without changing dimensions or competing with the focus outline; disabled uses `GrayText`. Fields take no pseudo-elements: see Fields.

Copy is in Loading from activation until the `navigator.clipboard.writeText()` promise settles, including while it waits for a permission decision. `aria-disabled` does not block activation by itself: the handler MUST also return without starting another write while one is pending (click, Enter and Space). Native `disabled` MUST NOT be used. Resolved or rejected, remove `aria-disabled` and `aria-busy` and return the button to its interactive state, without moving focus. Success is shown and announced only after the promise resolves; a rejection shows and announces an error, never success. Progress and result use the polite status region from the shared rules; the result follows the copy feedback colors in the article code rule.

### Fields

| State                             | Treatment                                                                                                                                              |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Default                           | `surface`, 1px `control-border`, `text`; visible label above; min height 48px; text 16px or more.                                                      |
| Hover                             | Border `text-muted`.                                                                                                                                   |
| Focus-visible                     | Border `accent` plus the shared ring.                                                                                                                  |
| Disabled                          | Disabled tokens, dashed border, native `disabled`.                                                                                                     |
| Read-only / submitting            | `surface-sunken`, `readonly`; keeps focus and value.                                                                                                   |
| Submitting: `select` and checkbox | `surface-sunken` on the field or row, `aria-disabled="true"`; keep focus and the submitted value.                                                      |
| Invalid                           | Border `danger` plus 1px inset, icon and message below, `aria-invalid`, `aria-describedby`. Only for field errors, never for network or server errors. |

Field precedence:

- Background: Disabled > Read-only (`surface-sunken`) > Default (`surface`).
- Border: Disabled > Invalid (`danger`) > Focus-visible (`accent`) > Read-only or Default (`control-border`) with Hover (`text-muted`) only on editable fields.
- The focus ring is added in every focusable state, including read-only and invalid. A read-only field is focusable, selectable and has no hover; it MAY also be invalid, keeping `aria-invalid` and its message. A disabled field shows no invalid state.
- `select` and checkboxes do not support `readonly`. On submit, values MUST be captured first and the controls locked afterwards. This lock MUST NOT use native `disabled` (nor a disabled `fieldset`), because it drops focus.
- While locked they stay focusable, with `aria-disabled="true"`, the Read-only look (solid `control-border`, no hover) and their value or mark visible; they do not take the Disabled treatment. A checkbox cancels `click` (which covers Space and label clicks). A `select` cancels opening and the keys that change the option, without intercepting Tab, Shift+Tab or Escape; because some native pickers cannot be cancelled, any `input` or `change` MUST restore the submitted value before it reaches form state. What is shown MUST always match what was sent.
- Locking does not move focus. When the response arrives `aria-disabled` is removed: on a request error focus stays and values are kept; on field errors it moves to the first invalid field; on success, if the focused control is no longer shown, it moves to the in-context confirmation (`tabindex="-1"`).
- Forced colors: `input`, `textarea` and `select` take no pseudo-elements and lose the inset shadow. An invalid field MUST use a real 2px solid `CanvasText` border with padding reduced by 1px, so dimensions do not change, plus its icon and message; the focus outline stays separate; disabled uses `GrayText`.

Placeholders are examples in `text-muted`, never the label. Counters use `meta`. Submit buttons SHOULD stay enabled and validate on submit.

### Cards and tags

- Card: `surface`, 1px `divider`, radius 16px, padding 24px, no shadow.
- A fully clickable card has one link, wrapping the title and stretched over the card by a pseudo-element; “Leer post” is plain text. Hover changes the border to `accent` and underlines the title; the ring surrounds the card (`:has(a:focus-visible)`); no lift or scale. Project cards provide an action at the bottom of the card.
- Tags are non-interactive: pill, 1px `divider`, `meta` size 12–13px, `text-muted`.

### Chat

- Panel: `surface`, level 1, 400×575px from 768px as height permits and full screen below. Short viewports use tighter spacing and a single row of horizontally scrollable suggestions. The header contains the title and close icon button.
- Assistant messages on `canvas` with `divider` border; user messages on `accent-subtle`; each shows its author in text. No bubble shadows.
- Suggestions use their own variant. The composer integrates the message field, the counter at bottom left and a 44×44px primary action at bottom right with an up arrow and the accessible name “Enviar”. While sending, the spinner occupies the same space.
- The panel uses 2px focus outlines with a 2px offset. The field focus outline surrounds the composer. Scrollable chat areas use thin scrollbars with the control border token.
- Starter errors align the message with the “Reintentar” action.
- Modal below 768px (`aria-modal`, focus contained, background inert); non-modal dialog above. Escape closes and returns focus to the launcher; the launcher leaves the tab order while open.
- The panel is a `role="dialog"` named with `aria-labelledby`. On open, focus goes to the message field. After sending from the field, the send button or a suggestion, focus moves to the message field; suggestions are Disabled while the reply is pending and may then be replaced. The message list is a named `role="log"`: each message added to it, from the user or the assistant, is announced politely without rereading the history. The typing placeholder is hidden from assistive technology and progress is announced in a separate `role="status"` region. Escape closes the non-modal panel only while focus is inside it. Crossing 768px while open updates `aria-modal` and `inert`.
- If focus moves under the non-modal panel, close the panel or scroll the focused element into view.
- Focus MUST never be hidden by the panel or launcher. At any viewport height, including 200% zoom, every control MUST stay reachable and operable by keyboard and touch, with the focused one visible.
- Loading starters use static-size placeholders; errors offer retry; fallback answers are labelled as before.

### Motion

- Motion answers an action: state changes 150ms, panel and toast entrance 200ms with opacity and up to 8px translate. Easing `cubic-bezier(0.2, 0, 0, 1)`.
- Internal anchors and “Volver arriba” use native smooth scrolling. The page avoids entrance animations on initial load or on scroll, initial opacity of 0, blur, hover scaling and looping decoration. Only progress indicators loop.
- The existing route transition remains for navigations after the first one and never runs on initial load.
- `prefers-reduced-motion: reduce`: no route transition, translate, smooth scroll or looping animation; changes are instant and progress is conveyed by text.

### Accessibility

- MUST meet WCAG 2.2 AA in both themes.
- Full keyboard operation in logical order; one H1 per view; landmarks; focus never obscured; focus managed after dialogs, errors and confirmations.
- Targets: at least 24×24px or a valid WCAG exception (MUST); 44×44px for touch controls (SHOULD; button variants already require it).
- Information never depends on color alone, hover or motion.
- Automated checks do not replace screen reader, zoom, browser and device validation.

### Prerendering and layout stability

- Content, titles, links and metadata MUST be present in prerendered HTML and readable without JavaScript; URLs and slugs do not change.
- Hydration MUST keep the prerendered DOM: no loading state replacing it, transferred state preserved.
- Lab CLS MUST stay at or below 0.10 on initial load. Theme changes are CSS-only and move nothing.
- Reserve space for images, async regions, suggestions, feedback and code toolbars. Content added after load does not push what is being read.
- Web fonts use `font-display: swap`; SHOULD use metric-adjusted fallbacks to reduce the font shift.

### Social preview metadata

- This repository owns the metadata: absolute `og:image`, `og:image:width` 1200, `og:image:height` 630, `og:image:alt` with the article title, and `twitter:card` `summary_large_image`, all in the prerendered HTML.
