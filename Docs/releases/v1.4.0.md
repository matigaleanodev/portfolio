# Portfolio v1.4.0

Site redesign, project pages and safer publication.

## Site and blog

- New "Índigo de taller" visual system, with light and dark themes following the system preference, applied to the home page, blog, articles, chat and unsubscribe page.
- A dedicated page for each project, with the technical decision, usage, contribution and architecture links.
- Blog ordering and search preserved when returning to the list, plus loading, error with retry and empty states.
- Wider reading column for articles, code copying and scrollable regions for code and tables.
- Prerendered content stays in place during startup instead of being replaced by a loading state.

## Chat, contact and subscription

- The chat gives priority to the conversation: compact suggestions that can be reopened, an input that grows with the draft and local questions when the initial load fails.
- Better focus and keyboard handling in the chat, which behaves as a dialog on small screens.
- Subscription feedback distinguishes new subscriptions, already subscribed addresses, invalid addresses and service errors.
- Unsubscribing from the website works again.

## SEO, privacy and accessibility

- Unknown routes show a 404 page instead of redirecting to the home page, and Hosting answers them with a 404 status.
- Consistent per-route metadata and indexing, project pages in the sitemap, RSS autodiscovery and the editorial sitemap declared in `robots.txt`.
- The unsubscribe address is removed from the URL before analytics loads.
- Visible control states and focus in forced colors mode; article images declare their dimensions.

## Delivery

- Continuous integration on pull requests and pushes to `dev` and `main`, without secrets or external services.
- Only the current head of `main` publishes, confirmed before each production effect.
- Chat knowledge publication no longer depends on release processing succeeding, and the release manifest includes each article excerpt.
- Firebase CLI pinned by lockfile and `main` to `dev` synchronization through a pull request.

## Available before this version

These changes came after v1.3.0 and were published without a version number:

- Connection to the serverless API on its definitive domain, preserving the contracts.
- Updated home page and architecture cases, with Modo Playa, Foodly Notes, Portfolio and Nora.
- AWS account check and a time limit in the publication workflow.

## Compatibility and publication

- Published routes and API contracts are preserved. `/projects/:slug` is new.
- Unsubscribing supports the new `#email=` links and the earlier `?email=` links.
- This frontend is published before the backend version that sends `#email=` links. With that backend active, the site must not return to a version without that support.
